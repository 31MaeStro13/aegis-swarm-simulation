# Техническое задание: Математическое ядро и алгоритмы 2D-симуляции

* **Исполнитель**: Дотун (Swarm Algorithms & Simulation)
* **Рабочая директория**: `docs/dotun/`, `simulation/`, `algorithms/`, `probability/`
* **Стек**: Python 3.12 (NumPy, SciPy, Pydantic). Запуск строго через `uv run`.
* **Главный документ MVP 0.1**: [`docs/dotun/AEGIS_SAR_TECHNICAL_SPECIFICATION_v0.1.md`](AEGIS_SAR_TECHNICAL_SPECIFICATION_v0.1.md)

---

## 1. Основная задача и зона ответственности
Разработка математического ядра и 2D-симулятора распределенного поиска для подтверждения эффективности роевого подхода. Дотун реализует модель пространства, алгоритмы разделения секторов, вероятностное обновление карты и динамический пересчет задач при отказе аппарата.

---

## 2. Разделение по этапам разработки

### Этап 1. MVP 0.1 — 2D Python-симулятор (текущий спринт до 4 декабря 2026)
*В рамках MVP 0.1 исключены 3D-модели деревьев, овраги, радиозатухание в листве и реальные выгрузки из закрытых баз поисковиков.*

1. **Дискретная среда поиска (2D Grid)**:
   - Базовая сетка: 40 × 40 ячеек (размер параметризован в конфигурации).
   - Дроны: 5 абстрактных аппаратов по умолчанию (с возможностью настройки от 1 до 10 в коде).
   - Движение: дискретное перемещение между центрами ячеек без сложной физики аэродинамики.
2. **Вероятностная модель (Probabilistic Search)**:
   - **Синтетическая априорная карта**: моделирование начального распределения вероятности нахождения человека (двумерное распределение Гаусса вокруг точки LKP).
   - *Важно*: в MVP 0.1 не используются нераскрытые статистические параметры Lost Person Behavior. Все вероятности строго синтетические и служат для демонстрации работы байесовского фильтра.
   - **Байесовский пересчет**: при обследовании ячейки дроном остаточная вероятность обнаружения цели в ней снижается с учетом заданной вероятности обнаружения ($P_{det} < 1.0$). Необследованные зоны сохраняют высокий приоритет.
3. **Алгоритм распределения территории и динамическая перебалансировка**:
   - Начальное разбиение зоны между 5 аппаратами (секторное / сеточное).
   - **Сценарий отказа (Ключевая демонстрация)**:
     - На шаге $T_{fail}$ принудительно эмулируется отказ одного из дронов.
     - Алгоритм фиксирует событие отказа и автоматически перераспределяет оставшиеся необследованные ячейки выбывшего борта между 4 активными дронами.
4. **Единый контракт данных (JSON DTO)**:
   - Дотун экспортирует снимки состояния симулятора в строгой JSON-схеме (согласованной с Олегом):
     - `grid_size`: размерность сетки [40, 40].
     - `probability_map`: матрица 40x40 float-значений.
     - `coverage_map`: матрица 40x40 int-значений (число обследований).
     - `drones`: список 5 объектов с полями `id`, `x`, `y`, `battery`, `status`.
     - `event_log`: список последних событий (включая отказ и перераспределение).
   - Этот JSON является источником правды для фронтенда Никиты и Rust-ядра Анастасии.

### Этап 2. Грант ФСИ (1 млн руб, 12 месяцев) — Пространственная модель и реальные данные
*Реализуется на 2 этапе проекта.*

1. **Усложнение среды**:
   - 3D-препятствия, моделирование растительности и перепада высот.
2. **Профили LPB (Lost Person Behavior)**:
   - Интеграция реальных профилей поведения потерявшихся (дети, пожилые, охотники) на базе открытых спасательных исследований (Р. Кестер и др.).

---

## 3. Результат этапа MVP 0.1
1. Автономный воспроизводимый Python-скрипт симулятора (`uv run run_simulation.py`), работающий с фиксированным сидом (`seed=42`).
2. Экспорт шагов симуляции в JSON для фронтенда Никиты.
3. Количественный отчет: сравнение эффективности поиска группой из 5 дронов против 1 одиночного дрона (сокращение времени закрытия 90% вероятности).
